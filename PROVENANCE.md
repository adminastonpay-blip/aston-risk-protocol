## SHA-256 checksums

The values below were calculated over the exact UTF-8 text returned by GitHub for the named files and then re-fetched from the public main branch to verify the manifest entries.

See [SHA256SUMS.txt](SHA256SUMS.txt). The manifest contains four entries (README.md, ASTON_RISK_PROTOCOL.md, LICENSING.md and PROVENANCE.md). Each entry must match the exact UTF-8 file contents on the same commit; the manifest itself is intentionally excluded to avoid a self-referential checksum.

## Separate controls not yet completed

- Author signature: not yet applied. A signing key must remain under the author's control; never share a private key in chat.
- Independent timestamp: not yet anchored. No OpenTimestamps proof or trusted timestamp-authority receipt is claimed.
- Patent filing or trademark registration: not claimed.

A Git commit ID or SHA-256 checksum is not proof of the author's legal identity or a trusted creation timestamp. For an independently verifiable timestamp, submit the final manifest or release artifact hash to OpenTimestamps (https://opentimestamps.org/) and preserve the returned proof, then verify it. For authorship authentication, sign a release tag using a private key controlled by the author and publish only the public key/fingerprint.
